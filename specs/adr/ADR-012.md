# Architecture Decision Record

## Context

`--download` fetches embedding and re-ranker model assets into a cache location
resolved per-process from `HF_HOME`, then `FASTEMBED_CACHE_DIR`, then a
`.fastembed_cache` directory relative to the current working directory
(OBS-014). The embedded database always lives under `~/.mdsearch/collections.db`.
The model assets therefore land outside the product's data directory, in a
location the user cannot predict, and a run from a different working directory
or environment silently resolves a different cache — so `embed` reports
"pass --download to fetch it" for a model that was already downloaded (OBS-015).

Availability is today detected by probing fastembed's internal hf-hub cache
layout (`refs/main` pointer plus the primary model file under a commit-named
`snapshots` folder) — a fragile, version-coupled check.

The approved product decision (DEC-016, EPIC-011) requires: a product-owned
default cache location under `.mdsearch`, reliable "downloaded" detection, and
truthful user guidance.

## Decision

1. **Resolution order and location.** The model cache directory is resolved in
   `app` (the composition root, per R-SEP-10 — configuration read once at
   startup, no `std::env::var` outside `app`) as: `HF_HOME`, then
   `FASTEMBED_CACHE_DIR`, then the product default `~/.mdsearch/models`. The
   working-directory `.fastembed_cache` fallback is removed, and legacy
   downloads in it are not migrated or reused (one re-download after upgrade).
   The resolved directory is passed to the adapters as a required cache
   directory, so the adapters no longer resolve anything themselves.

2. **Completion-marker availability.** "Downloaded" means a per-model
   completion marker file exists: `{cache_dir}/{model}.completed`, where
   `{model}` is the domain model name (`EmbeddingModel::as_str()` /
   `RerankerModel::as_str()`). The marker is written atomically (temp file +
   rename) immediately after a successful session build/download. Availability
   checks (`ensure_available`, the lazy session builds in `embed`/`rerank`)
   test marker presence; the hf-hub layout probe is deleted. Marker naming is
   adapter-internal and is the only thing that needs to change if the layout
   changes.

3. **Session lifecycle unchanged.** `ensure_available` with `download=true`
   builds the session (which downloads), writes the marker, and caches the
   session for the process; a marker-write failure fails the run cleanly with
   no collection modified (REQ-010 FR-010 semantics). With `download=false`,
   a missing marker fails before any collection work with the existing
   "not available locally; pass --download" error.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Keep the hf-hub layout probe, pointed at the new location | Still fragile and version-coupled: `refs/main` may be absent after partial fetches and layout drift breaks detection; the marker is deterministic and testable |
| Resolve the cache next to the `--database` file | The location becomes run-dependent again, reintroducing the OBS-015 false-positive class; `~/.mdsearch` stays the canonical data home |
| Make `.mdsearch` authoritative and ignore `HF_HOME`/`FASTEMBED_CACHE_DIR` | Breaks users who deliberately set these variables; overrides preserve ecosystem compatibility while the default becomes predictable |
| Keep resolution inside the adapters, adding a home-directory lookup there | Duplicates configuration reading in adapters and violates R-SEP-10; `app` already knows the home directory |
| Full-file manifest verifying every model asset | Over-engineered: the marker contract accepts that externally deleted files surface as a storage error at session build, and a marker proves the download completed |

## Consequences

### Positive

- Predictable, documented default (`~/.mdsearch/models`): everything the tool
  persists lives under `.mdsearch`; downloads no longer depend on the current
  working directory.
- Availability detection is deterministic and independent of fastembed's
  internal layout; the false "pass --download" advice disappears.
- Environment overrides keep working for users who manage model caches
  centrally.
- No port, domain, or use-case changes: the contract of
  `EmbeddingGenerator`/`Reranker` is untouched.

### Negative Or Tradeoffs

- One-time re-download for users with assets in a legacy `.fastembed_cache`
  location.
- Marker-only detection: if model files are deleted externally while the
  marker remains, the model counts as downloaded and the failure surfaces as a
  storage error at session build rather than as a download suggestion.
- The adapters' constructor signatures change (required cache directory
  instead of an optional one); `app` is the only production caller, so the
  blast radius is small.

## Follow-Up Actions

- Implement the resolution helper and constructor changes in `app` and the
  `embed-fastembed` adapters (DES-017).
- Update the README and the `--download` CLI help with the resolution order.
- Add adapter unit tests for marker helpers and availability short-circuit,
  and app unit tests for the resolution order.
