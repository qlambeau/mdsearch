# Architecture Decision Record

## Context

`SqliteFileStore::reconcile` currently commits file, lexical, and graph changes
in one transaction. Semantic embeddings are generated by a separate use case
and written by `SqliteSemanticIndexStore` in a separate transaction. US-022
requires an update failure to preserve the collection's old files and every
configured index. It also requires a global embedding-model change to preserve
the old model and all old semantic indexes if any collection cannot be rebuilt.

Embedding inference is CPU-intensive and can take much longer than the database
write. The global vector table may also need to be recreated when the model's
dimension changes (ADR-010).

## Decision

Prepare semantic embeddings before entering a SQLite write transaction, then
commit the staged results together with the state they describe:

1. A source-aware collection update uses one SQLite transaction to reconcile
   stored files, rebuild the lexical index and graph, and either replace the
   enabled semantic index or remove vectors/state for a disabled collection.
   The transaction is owned by the existing SQLite file-store boundary, which
   already atomically commits files, lexical passages, and graph state. Extend
   that boundary with the staged semantic payload rather than adding a new
   adapter layer.
2. A database-wide embedding-model change stages results for all
   semantic-enabled collections, then uses one SQLite transaction to update
   the global model setting, recreate the shared vector table if required,
   replace every affected collection's vectors and state, and commit. A failure
   rolls back the setting and all semantic indexes together.
3. A re-ranker-only change updates its global setting without touching the
   vector table or semantic-index state.

Both the existing `embed` command and the new `model set` operation use the
same atomic model-change path. The legacy `embed` command requires semantic
indexing to be enabled and does not change collection policy.

Embedding results are associated with a discovered file path and logical
passage kind/position until the transaction resolves the final SQLite file ID.
Persisted vectors retain the `(file_id, kind, position)` identity from ADR-006.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Run model inference while holding the SQLite write transaction | Keeps the write lock for the full CPU-bound inference and increases contention |
| Commit a global model switch in one transaction per collection | A later failure can leave mixed models and violates the database-wide model invariant |
| Update settings first and restore them on failure | Compensation can itself fail and briefly exposes an invalid setting/index combination |
| Add a separate combined-index adapter or crate | Existing stores own the SQLite transaction and required tables; another layer would duplicate persistence responsibility |
| Persist a new vector table beside the old one and swap after rebuilding | Adds temporary schema objects, cleanup paths, and more dimension-specific recovery without removing the need to test atomic DDL |

## Consequences

### Positive

- Expensive inference completes before acquiring the SQLite write lock.
- Collection updates and global model changes preserve the prior searchable
  state on failure.
- Dimension changes and model settings cannot commit separately from rebuilt
  vectors.
- Existing ports and adapters remain the architectural boundary; no dependency
  or workspace member is added.

### Negative Or Tradeoffs

- Staging a global model change requires memory proportional to the embeddings
  for all semantic-enabled collections.
- Existing application ports gain richer staged-index contracts and their test
  fakes must implement the same atomic behavior.
- The vendored vector extension's transactional behavior, including table
  recreation, must be verified by integration tests before implementation is
  considered complete.

## Follow-Up Actions

- Extend the existing file-store transaction contract to commit prepared
  semantic updates and disabled-index cleanup with files, lexical, and graph
  state.
- Add one semantic-store operation that commits global model settings and all
  staged collection vectors/state in one transaction.
- Verify rollback after failures at vector insertion, semantic-state writes,
  dimension changes, and final commit.
- Ensure both old and new model command paths use the shared atomic operation.
