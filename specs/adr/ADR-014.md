# Architecture Decision Record

## Context

Knowledge graph extraction parses only standard markdown links
(`[label](target.md)`) (OBS-009). The primary target domain — developer
markdown knowledge vaults (Obsidian, Logseq, Foam, Dendron, QMD) —
predominantly cross-references via wikilinks (`[[note]]`, `[[note|label]]`,
`[[path/note#heading]]`), so graphs extracted from such vaults stay largely
disconnected and `--related`/`graph neighbors` miss document relationships.

The approved product decision (DEC-018, EPIC-013) requires wikilink
extraction as `LINKS_TO` edges alongside standard markdown links, resolving
against known collection files with Obsidian-style case-insensitive matching.

## Decision

1. **Forms.** `[[target]]`, `[[target|label]]`, `[[path/target#heading]]`, and
   `[[target#heading|label]]` are recognized. The piped label is display text
   only — it creates no nodes and no `ALIAS_OF` edges. A header fragment is
   stripped before resolution; the edge targets the file. A bare self-anchor
   (`[[#heading]]`) produces no cross-file edge. `[[...]]` is closed by the
   first `]]`.

2. **Resolution.** A new domain resolution path (`resolve_wikilink`) mirrors
   `resolve_file`'s candidate strategy — target as-is, joined onto the source
   file's directory, `.md`-appended variants, then a basename match — but
   matches known collection paths case-insensitively. A candidate with more
   than one case-insensitive match (e.g. `Note.md` and `note.md`) is treated
   as ambiguous and skipped. `resolve_file` itself is unchanged: standard
   markdown links keep exact matching.

3. **Self-edges.** A resolved wikilink whose target is the source file itself
   is skipped. Standard markdown links keep their existing behavior
   (unchanged, including any self-link behavior).

4. **Placement.** The change is confined to the domain graph extraction
   (`crates/domain/src/graph.rs`): a `inline_wikilinks` extractor and a
   `resolve_wikilink` resolver, wired into `extract_graph` additively. No
   schema, store, adapter, CLI, or `resolve_file` changes.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Register piped labels as `Alias` nodes with `ALIAS_OF` edges | Richer graph but adds a node kind, more edges, and query surface; the label is display text, and the existing markdown-link form sets the precedent of ignoring it |
| Case-sensitive resolution | Obsidian and most wikilink tools resolve case-insensitively; case-sensitive matching leaves common `[[Note]]`-to-`note.md` links dangling |
| Make `resolve_file` case-insensitive for all link forms | Changes existing markdown-link behavior and risks silently re-resolving previously-unresolved links; wikilinks get their own resolution path |
| Code-fence-aware wikilink extraction | Separate observation (OBS-010); excluded to keep this slice small and behavior additive |
| Support embeds (`![[note]]`) and block references (`[[^block]]`) | Different semantics (embedding vs. linking); out of scope for this epic |

## Consequences

### Positive

- Wikilink-based vaults produce connected graphs; `--related` and
  `graph neighbors` surface real relationships with no schema change.
- Additive: standard markdown-link behavior, output shapes, and all other
  graph features are untouched; the change is confined to the pure domain
  layer.
- Deterministic and testable: forms, case-insensitivity, ambiguity, and
  self-link rules are pure functions.

### Negative Or Tradeoffs

- Case-insensitive resolution may resolve a link to a different file than a
  human intended when only case differs; the ambiguity rule skips such cases
  rather than guessing.
- A file linking to itself via a wikilink produces no edge, while a
  self-referencing markdown link still produces one (behavior preserved,
  slightly inconsistent).
- Wikilinks inside code fences can still create phantom edges (deferred to
  OBS-010).

## Follow-Up Actions

- Implement `inline_wikilinks`, `resolve_wikilink`, and the `extract_graph`

- Extend the `012-entity-graph` scenarios and the domain/store tests for the
