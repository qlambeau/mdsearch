# Architecture Decision Record

## Context

The Rust Engineering Constitution described a canonical layout using a root
`CONSTITUTION.md`, `docs/specs/`, and `docs/adr/`. This repository is an SDD
Workflow Kit and its actual, established layout uses `specs/CONSTITUTION.md`,
`specs/`, `specs/prds/`, `specs/adr/`, `specs/templates/`, feature packets, and
`specs/archive/`.

The mismatch created an implementation blocker because agents were required to
obey the constitution while also following the repository's approved workflow.

The current-session human explicitly authorized an exceptional amendment to the
constitution and requested that the deviation be recorded in this ADR.

## Decision

Adopt the repository's current specification layout as the constitution's
repository-specific layout:

- The constitution is `specs/CONSTITUTION.md`.
- Product PRDs live under `specs/prds/`.
- ADRs live under `specs/adr/`.
- Feature specifications live under `specs/NNN-feature-slug/`.
- Templates live under `specs/templates/`.
- Completed feature specifications are archived under `specs/archive/`.

The future Rust workspace still follows the constitution's dependency and layer
rules, including `crates/domain`, `crates/application`, technology adapters,
infrastructure, and the composition-root application crate.

This is a one-time, human-authorized deviation from the constitution's previous
agent-amendment prohibition. It does not authorize agents to amend the
constitution in future sessions without an equivalent explicit human decision
and accompanying ADR.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Move the workflow kit to `docs/specs/` and `docs/adr/` | Would restructure established paths and invalidate the approved workflow references |
| Keep the constitution's old layout example | Leaves the conflict in place and makes Rust implementation ambiguous |
| Maintain a permanent undocumented exception | Rejected because the constitution requires deviations to be recorded and reviewable |

## Consequences

### Positive

- The constitution, AGENTS guidance, skills, and specification workflow use the same paths.
- Future agents can locate the normative constitution and feature packet without guessing.
- Existing approved artifacts do not need to be moved again.
- Rust layer and dependency rules remain unchanged.

### Negative Or Tradeoffs

- The constitution now contains repository-specific layout guidance rather than only its former generic example.
- Future repository layout changes require another explicit amendment and ADR.
- The Rust workspace has not yet been created, so its eventual implementation paths remain subject to the constitution's layer rules.

## Follow-Up Actions

- Update repository guidance and feature tasks to reference `specs/CONSTITUTION.md`.
- Remove the layout blocker from implementation planning.
- Revisit the future Rust workspace layout before the first Rust implementation edit.
