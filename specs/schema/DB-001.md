# Database Schema: Collections Database

## Database Overview

The Collections Database is the single-file, embedded SQLite database that serves
as the central system of record for all collections, markdown file metadata,
lexical search indexes, semantic vector embeddings, and contextual entity graphs
managed by `mdsearch`.

- **Engine:** SQLite 3 (via bundled `rusqlite` and `sqlite3_ext`)
- **Default Location:** `~/.mdsearch/collections.db`
- **Override Flag:** `--database PATH`
- **Concurrency & Locking:** In-process single-binary access with transactional consistency. Parent directories are created automatically if missing upon initialization.

## Configuration & Extensions

- **`sqlite-vector`:** Statically integrated and registered at connection startup via virtual table module (`CREATE VIRTUAL TABLE ... USING vector(...)`) and scalar functions (`vector_from_json`, `knn_match`).
- **FTS5:** Used by the lexical index tables introduced in schema version 3 (EPIC-003): `passages`, `passage_files`, and `lexical_index_state`.

## Schema Evolution & Migrations

The database maintains an internal migration version table (`schema_version`).

| Version | Applied In | Description |
| --- | --- | --- |
| 1 | `001-create-collection` | Initial schema: `schema_version` and `collections` tables |
| 2 | `004-add-files` | Adds the `files` table for ingested markdown content and metadata |
| 3 | `006-lexical-index` | Adds the `passages` FTS5 virtual table, the `passage_files` mapping, and `lexical_index_state` for the lexical index built by `collection update` |
